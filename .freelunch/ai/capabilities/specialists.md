# Specialist Routing

Use specialist perspectives only when the changed surface warrants them. The role selection is adapted from the pinned Agency Agents files in `ai-stack.lock.json`.

| Changed surface                                                    | Internal perspective          |
| ------------------------------------------------------------------ | ----------------------------- |
| Cross-module design or durable interface                           | Software architect            |
| CI/CD, release, or infrastructure automation                       | DevOps automator              |
| Reliability, observability, or operations                          | SRE                           |
| User or contributor documentation                                  | Technical writer              |
| Changed behavior and automated verification                        | Test automation engineer      |
| Evidence quality and release confidence                            | Reality checker               |
| Authentication, authorization, input, secrets, or trust boundaries | Application security engineer |
| Independent maintainability review                                 | Code reviewer                 |

Load the relevant capability reference and apply the perspective inside the current public workflow. Do not register these roles as separate agents, commands, or skills.

When multiple perspectives are useful, the main workflow remains responsible for reconciling conflicts and presenting one evidence-based result. Parallel or isolated reviewers are optional client capabilities, not required workflow steps.
